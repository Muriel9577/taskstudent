# TaskStudent. Початковий план агента (версія 1, ДО правок студента)

Агент: Claude (Anthropic). Дата: 2026-11-20.

## 1. Аналіз задачі

Продукт: веб-застосунок, де викладач створює предмети й завдання з балами та задає прохідний бал,
а студент бачить свої завдання, прогрес по предмету у відсотках і набрані бали відносно прохідного.

Проблема: студенти розпорошують облік завдань і не бачать, скільки ще треба для заліку.
Цільові користувачі: студент, викладач.

## 2. Функціональні можливості (5)

1. Авторизація з двома ролями (student, teacher).
2. Редактор викладача: створення й редагування предметів і завдань (назва, опис, дедлайн, макс. бал); прохідний бал предмета.
3. Приєднання студента до предмета за кодом.
4. Виконання завдань студентом (статус) і виставлення балів викладачем.
5. Прогрес по предмету: відсоток виконаних завдань (кільце) і бали студента відносно прохідного.

Календар дедлайнів: простий перегляд за датою (за потреби, 6-та функція).
Відкладено: нагадування, навчальні матеріали, темна тема, статистика за період.

## 3. Архітектура

Клієнт-серверний застосунок: Flask (REST API + статичні сторінки), SQLite, HTML/JS без зовнішніх бібліотек.

Шари:
- api (маршрути, перевірка ролей)
- services (бізнес-логіка: прогрес, бали)
- db (схема та доступ до SQLite)
- static (інтерфейс студента і редактор викладача)

## 4. Модель даних

User(id, email, password_hash, name, role)
Subject(id, teacher_id, title, description, pass_score, join_code)
Task(id, subject_id, title, description, deadline, max_score)
Enrollment(student_id, subject_id)
Submission(student_id, task_id, status, score)

## 5. Послідовність реалізації

1. Каркас проєкту, схема БД, тести схеми.
2. Реєстрація / вхід, ролі.
3. Редактор викладача (предмети, завдання, прохідний бал).
4. Приєднання студента за кодом, список предметів.
5. Виконання завдань, виставлення балів.
6. Підрахунок прогресу та балів (services) + інтерфейс кільця.
7. Тести, перевірка граничних випадків, code review.

## 6. Технічні ризики

- Предмет без завдань: ділення на нуль при підрахунку відсотка.
- Бал більший за максимальний або від'ємний.
- Студент бачить чужі предмети / викладач редагує чужі предмети (перевірка прав).
- Зберігання паролів (тільки хеші).
- Повторне приєднання до предмета, неправильний код.
- Зміна max_score після виставлення балів.
